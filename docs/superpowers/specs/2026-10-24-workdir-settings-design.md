# 工作目录与设置面板设计规格

**日期：** 2026-10-24  
**状态：** 已与用户逐节对齐，待用户审阅本文件  
**参考：** httptest 的 `httptest [DIR]` 与 `.httptest/` 本机目录；当前 httpproxy 的紧凑抓包界面

## 1. 目标

用指定目录启动 httpproxy。配置和 CA 落在该目录的 `.httpproxy/` 里。界面左侧增加一条窄活动栏，左下角是设置。设置页修改配置文件里的监听地址、保留条数、正文上限和主题。

成功标准：

- `httpproxy [DIR]` 能打开一个已存在的目录。省略目录时用当前目录。
- 首次启动创建 `.httpproxy/`，其中有配置、CA 和一份忽略全部内容的 `.gitignore`。
- 设置页编辑的是文件里的值。保存写入文件，不把命令行覆盖写进去。
- 代理地址和 UI 地址旁边始终标出这次实际在听的地址，新地址重启后才生效。
- 保留条数和正文上限在这次命令行没有对应覆盖时，保存后对这次进程生效。主题保存后立刻生效。
- 顶栏不再放主题开关。「下载 CA」和「清空」仍在顶栏。

## 2. 非目标

- 不从 `~/.httpproxy` 迁移旧证书或旧配置。
- 不在应用内重启进程，也不在保存后重新监听。
- 不把这次的命令行覆盖写回配置文件。
- 不在设置里修改列显示。列显示仍用浏览器本地的 `httpproxy.columns`。
- 不加设置分类栏，不加活动栏里的其他图标。
- 不把抓包记录落到磁盘。
- 不新加 npm 依赖，不加前端路由。
- 不改抓包协议、过滤、详情和 WebSocket 上现有的流量事件。

## 3. 启动与目录

```text
httpproxy [DIR] [-proxy ADDR] [-ui ADDR] [-max-flows N] [-max-body N]
```

`DIR` 最多一个，必须已经存在并且是目录。省略则用进程的当前目录。相对路径按进程当前目录做 `filepath.Abs`。不调用 `os.Chdir`。Go 里不展开 `~`。

标志可以出现在 `DIR` 前后。单独的 `--` 之后全部当作位置参数。解析方式与 httptest 相同：先把 argv 拆成标志和位置参数，再交给 `flag.FlagSet`。不引入新的命令行库。

去掉 `-ca-dir`。再出现这个标志时，按无法识别的标志处理。

| 情况 | 退出码 |
| --- | --- |
| 无法识别的标志、标志的值不在允许范围、位置参数多于一个、`DIR` 不存在或不是目录 | 2 |
| 建不起 `.httpproxy/`、权限改不到位、配置非法、CA 不完整、监听失败 | 1 |

标志能被 `flag` 解析，但地址或数量不在本节的允许范围时，退出码仍是 2，并且还没有创建 `.httpproxy/`。参数不合法时不要创建这个目录。stderr 用英文。

工作区根就是 `DIR`。配置和 CA 放在它下面的 `.httpproxy/`。这个路径如果已经存在但不是目录，退出码 1。需要时创建它，并把权限设为 `0700`。目录已经存在时，启动也把它收到 `0700`，收不到则以退出码 1 结束。先收权限，再写配置和证书；证书加载不得把目录权限放宽。

```text
<DIR>/.httpproxy/          # 0700
  .gitignore               # 不存在时写入 *\n；已有内容不覆盖
  config.yaml              # 0644
  ca.crt
  ca.key                   # 0600
```

不创建、不修改工作区根目录的 `.gitignore`。`*` 会盖住证书初始化留下的锁文件。

证书仍由现有 `internal/cert` 生成和读取，目录改为 `.httpproxy/`。两个文件都没有时生成；只有一个时失败；密钥权限仍是 `0600`。

`config.yaml` 不存在时，用临时文件写入下列默认值再改名换上：

```yaml
proxy: 127.0.0.1:8080
ui: 127.0.0.1:8081
max_flows: 1000
max_body: 1048576
theme: dark
```

已有的 `config.yaml` 内容非法时，保持原文件，退出码 1。启动不会把它改写成默认值。这次启动仍可把目录收到 `0700`，并在 `.gitignore` 缺失时补上。

用 `gopkg.in/yaml.v3` 解析。五个字段都必须在，类型必须对：地址和主题是字符串，两个数量是整数而不是字符串或小数。多出来的字段视为非法。主题只能是 `dark` 或 `light`。地址必须能被 `net.SplitHostPort` 解析，因此 `:8080` 和 `[::1]:8080` 都合法。`max_flows` 是能放进 Go `int` 且大于等于 1 的整数。`max_body` 是能放进 Go `int64` 且大于等于 0 的整数。

这次进程实际使用的值先取文件，再用命令行盖住。只有 argv 里真正出现过的标志才算覆盖，不用「和默认值相不相等」来判断。主题没有命令行标志。首次写成的默认文件不包含这次的命令行覆盖。

覆盖只影响这次进程：

| 字段 | argv 里没有对应标志 | argv 里有对应标志 |
| --- | --- | --- |
| 代理地址、UI 地址 | 听文件里的地址 | 听标志里的地址 |
| 保留条数、正文上限 | 用文件里的值，保存后按第 5 节立刻生效 | 用标志里的值，直到重启 |
| 主题 | 始终用文件里的值，保存后立刻换肤 | 无此标志 |

无论这次有没有地址标志，保存后的新地址都要重启才开始听。

## 4. 界面

抓包仍是现在的顶栏、过滤条、上表和下详情。左边加一条常驻活动栏。

```text
┌ 顶栏 36px：标题 · 代理 <实际地址> · 条数 · 下载 CA · 清空 ┐
├──┬────────────────────────────────────────────────────────┤
│  │ 抓包：过滤条 · 表格 · 详情                              │
│  │ 或设置表单                                              │
│⚙│                                                        │
└──┴────────────────────────────────────────────────────────┘
 32px
```

活动栏宽 32px。深色背景 `#010409`，浅色背景 `#f6f8fa`，用变量 `--activity`。栏里只有左下角的齿轮，可见名称和 `aria-label` 都是「设置」。设置打开时，齿轮左侧有一条 2px 的强调线。点一下进入设置，再点一下回到抓包。刷新后回到抓包，不记住上次停在哪一页。

顶栏去掉主题按钮。代理地址显示这次实际在听的地址，悬停文案仍是「将客户端的 HTTP(S) 代理指向此地址」。条数、下载 CA、清空保留。停在设置页时，清空仍然清空流量，条数仍然跟着变。WebSocket 不断开。

设置占满活动栏右侧。过滤条、表格和详情不显示。页面只有一张表单，没有分类列。字号 12px，行高 22px，控件沿用现有按钮和输入框。

表单从文件值填入，改动先留在草稿里：

| 标签 | 草稿 | 旁边的说明 |
| --- | --- | --- |
| 主题 | 黑色 / 浅色，对应 `dark` / `light` | 无。保存成功后当前页才换肤 |
| 代理地址 | 文件里的地址 | 始终显示「当前」加这次实际地址，并显示「重启后生效」 |
| UI 地址 | 文件里的地址 | 同上 |
| 保留条数 | 文件里的整数 | 和这次实际值不同时显示「本次实际」 |
| 正文上限 | 文件里的整数 | 和这次实际值不同时显示「本次实际」 |

「保存」把草稿写回文件。保存失败时，输入框保留刚填的内容，错误文案出现在按钮旁。读取配置失败时不显示可编辑表单，只显示「无法读取配置」，并且不能保存。读取成功之前也不能保存。请求进行中按钮不可用。

列选择仍在抓包视图的过滤条上，不进入这张表单。

## 5. 数据流与接口

`internal/config` 负责读写 `config.yaml`、校验和计算这次的实际值。`cmd/httpproxy` 负责拆 argv、检查目录和退出码。`internal/api` 提供下面两个接口。`internal/store` 提供修改保留条数的方法。`internal/proxy` 让一条 flow 在创建时记下正文上限。`internal/ui` 在送出首页时写上主题。

`GET /api/config` 和成功的 `PUT /api/config` 都返回：

```json
{
  "file": {
    "proxy": "127.0.0.1:8080",
    "ui": "127.0.0.1:8081",
    "max_flows": 1000,
    "max_body": 1048576,
    "theme": "dark"
  },
  "runtime": {
    "proxy": "127.0.0.1:8080",
    "ui": "127.0.0.1:8081",
    "max_flows": 1000,
    "max_body": 1048576,
    "theme": "dark"
  }
}
```

设置页的输入框绑定 `file`。地址旁的「当前」和顶栏的代理地址绑定 `runtime` 里的地址。抓包列表的条数上限用 `runtime.max_flows`。

`PUT /api/config` 的正文就是这五个文件字段。缺字段、JSON `null`，或这五项以外的字段，都拒绝。数量必须是 JSON 整数，不能带小数。校验顺序固定为代理地址、UI 地址、保留条数、正文上限、主题，再检查缺字段和未知字段，只返回第一条错误。

通过后，把五个字段按上面的顺序写成 YAML，用 `.httpproxy/` 里的临时文件改名换上 `config.yaml`。不保留原文件里的注释和多余空行。响应体是保存之后的文件值和实际值。

保存之后：

- 代理地址和 UI 地址不重新监听。`runtime` 里的地址保持打开进程时的值。
- 保留条数在这次没有 `-max-flows` 时立刻改环形容量。容量变小就淘汰最旧的记录，并按现有方式逐条发送 `flow.evicted`。有 `-max-flows` 时容量不变。
- 正文上限在这次没有 `-max-body` 时，之后新创建的 flow 使用新上限；创建时把上限记在这条 flow 上，请求体和响应体都用这个值。已经在收的 flow 继续用创建时的上限。有 `-max-body` 时上限不变。
- 主题写入 `runtime.theme`，当前页面立刻换肤。

嵌入的首页在送出时把 `<html lang="zh-CN">` 写成带 `data-theme` 的形式，值是 `runtime.theme`。`web/index.html` 删掉读取 `localStorage` 键 `httpproxy.theme` 的脚本，避免它盖掉注入的主题。Vite 开发模式没有这次注入，页面先按黑色画出，`GET` 成功后再换成 `runtime.theme`。`GET` 失败时，已经画上的主题保持不变；抓包列表仍按 1000 条裁剪。

配置变更不走 WebSocket。另一个浏览器标签在刷新时重新拿到主题和配置。

接口错误用 JSON `{"error":"..."}`。`error` 用中文：

| 状态 | 文案 |
| --- | --- |
| 400 | 代理地址必须是 host:port |
| 400 | UI 地址必须是 host:port |
| 400 | 保留条数必须是大于等于 1 的整数 |
| 400 | 正文上限必须是大于等于 0 的整数 |
| 400 | 主题必须是 dark 或 light |
| 400 | 配置缺少字段 |
| 400 | 配置含有未知字段 |
| 400 | 配置不是合法的 JSON |
| 500 | 无法写入配置 |

启动失败的 stderr 用对应英文，例如 `invalid proxy address`、`invalid ui address`、`max_flows must be an integer >= 1`、`missing config field`、`unknown config field`。写入失败带上系统错误。

没有应用内的重启。用户自己重新运行 `httpproxy`，再打开新的 UI 地址。

现有的本机 Host 限制继续包住这些接口。

## 6. 测试与文档

`go test ./...` 至少覆盖：

- 首次创建后目录是 `0700`，`config.yaml` 是默认内容，`.gitignore` 是 `*\n`，`ca.key` 是 `0600`。
- 已有 `.gitignore` 不被覆盖。已有非法 `config.yaml` 不被改写，加载失败。
- 目录已存在但权限更宽时，启动后收到 `0700`。
- `:8080` 与 `[::1]:8080` 可以通过校验。小数、字符串数量、未知字段、缺字段不能通过。
- 省略目录、目录在标志前、目录在标志后都能解析。多余位置参数、目录不存在、`-ca-dir`、以及 `-max-flows 0` 这类越界标志，退出码是 2，且不会因此新建 `.httpproxy/`。
- argv 里出现的 `-max-flows` 在保存新条数后仍然是这次的实际容量；没有该标志时，缩小容量会淘汰最旧记录并发出 `flow.evicted`。
- 保存新的代理地址或 UI 地址不改变 `runtime` 里的地址。
- 保存主题会改变 `runtime.theme`。
- 400 响应不改文件。`GET` 同时返回 `file` 和 `runtime`。
- 送出的首页带有这次的 `data-theme`，并且响应里不再读取 `httpproxy.theme`。

`cd web && npm test` 与 `npm run build` 通过。列选择的现有测试保留。

实现时更新英文 `README.md`：命令写成 `httpproxy [DIR]`，说明 `.httpproxy/` 的布局，删掉 `-ca-dir`，写明主题和监听配置在设置里修改，并写明不会读取 `~/.httpproxy`。
