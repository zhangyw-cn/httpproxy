# HTTPS 热路径加速设计规格

**日期：** 2026-10-26  
**状态：** 待审阅  
**范围：** `internal/proxy` 的上游连接复用、TLS 会话恢复，以及把记录移出转发路径。存储、WebSocket、界面和证书签发保持原样。

## 1. 目标

同一主机第二次及以后的 HTTPS 请求，代理多出来的时间不超过 10 毫秒。头和正文仍然完整解密并记录，上限仍是 `max_body`。

成功标准：

- 本机基准里，预热之后，1 KB 响应经代理的中位往返时间减去直连的中位往返时间，不超过 10 毫秒。这个数字不作为 `go test` 的失败条件。
- 重复访问优先复用上游连接。必须新建连接时使用 TLS 会话恢复。
- 每条流量仍记录请求头、响应头、两侧正文（不超过该流量开始时的 `max_body`）、原始大小、截断标志，以及可解压时的展示副本。
- 界面按流量 id 覆盖整行。同一条流量先 `flow.created`，再 `flow.updated`。后到的创建事件不会把已经完成的行盖回进行中。

第一次访问某个主机可以多一次到目标站的完整 TLS 握手。

## 2. 非目标

- 不优化第一次叶子证书的签发，不在各主机之间共用叶子私钥。
- 不增加按主机跳过解密的直通隧道。
- 不把大文件吞吐或界面帧率当作本次目标。
- 不改 `FlowSink`、存储、WebSocket 消息和前端。
- 不改 `DisableCompression`，不改 ALPN（`h2` 与 `http/1.1`）。
- 不改客户端到代理这一侧的 TLS 会话票据，沿用 Go 默认。
- 不新加响应头超时。`ExpectContinueTimeout` 保持 1 秒。

## 3. 热路径

队列有空位时，连接上的 goroutine 只做转发，记录在记录器上完成。

```text
客户端连接
  读请求，套上请求体截取
  入队「开始」（队列满则整段就地记录）
  RoundTrip          ← 存储和 WebSocket 不排在这一步前面
  边写响应边截取
  关闭响应体         ← 上游连接回到池里
  入队「完成」
  回去读下一个请求

记录器（单 goroutine）
  开始 → OnCreated
  完成 → result()、解压、OnUpdated
```

队列有空位时如上。队列满时，新的流量整段就地记录，见第 5 节。

耗时在响应写完客户端之后、解压之前算完。入队和就地记录都如此。`DurationMs` 不含解压和入库。

慢的上游会先出现进行中的一行。本地很快的上游可能只在界面上看到最终状态，内容仍然完整。

WebSocket 升到 `101` 之后的双向转发仍占着原来的连接。记下来的耗时停在升级完成，隧道结束时不再更新这条流量。

## 4. 上游连接

主传输在主机名和拨号地址一致时使用：

| 参数 | 值 |
|---|---|
| 每主机空闲连接 `MaxIdleConnsPerHost` | 6 |
| 总空闲连接 `MaxIdleConns` | 128 |
| 空闲保留 `IdleConnTimeout` | 90 秒 |
| TLS 会话缓存 | 容量 128，LRU |
| 握手超时 | 10 秒 |
| 拨号超时 / TCP keepalive | 30 秒 / 30 秒 |

6 条对齐浏览器对同一主机的并行 HTTP/1.1 连接。HTTP/2 仍是一条连接多路复用。会话缓存服务「这个主机刚才访问过，但池里暂时没有空闲连接」：TLS 1.2 少一个往返，TLS 1.3 省掉重复的证书校验。

`MaxIdleConnsPerHost` 必须写成 6。Go 里 0 表示默认的 2，不能用来表示「不保留空闲连接」。

CONNECT 的目标是 IP、SNI 是域名时，按「拨号地址 + SNI」缓存传输。拨号地址用 `req.URL.Host`（含端口），SNI 用主机名。最多 32 组。每次取用都算一次使用，满了就淘汰最久未取用的一组。每组只服务一个拨号地址，`MaxIdleConns` 和 `MaxIdleConnsPerHost` 都是 6，`ServerName` 固定为该 SNI。会话缓存、空闲时间、拨号超时和握手超时与主传输相同，不必共用同一个 `Dialer` 对象。淘汰时只关闭该组的空闲连接；已经在进行的请求继续走完。查找锁在 `RoundTrip` 期间不持有。

`Proxy.Close` 关闭主传输和这些缓存传输上的空闲连接。测试可以在第一次拨号前打开 `DisableKeepAlives`。默认关闭，正式路径保留空闲连接。

## 5. 记录交接

记录器在 `New` 时启动，排在现有 `FlowSink` 前面。队列容量默认 64。测试可以在 `ListenAndServe` 之前把容量改小，也可以在记录器取出下一条任务前把它拦住。闸门只给测试用，默认放行。

一次成功的请求是两个任务：

1. **开始。** 请求头已经复制、请求体截取已经套上之后入队。快照只有头，没有正文，也不持有还在增长的截取缓冲。然后马上 `RoundTrip`。记录器取出后调用 `OnCreated`。
2. **完成。** 两侧正文都读完、响应体已经关闭之后入队。任务带上状态码、响应头、两侧截取缓冲、耗时和错误文本。记录器取出后调用 `result()`，再按现有规则做 `gzip` / `br` / `deflate` 解压，然后 `OnUpdated`。连接在入队之后不再写这两个缓冲。

队列按入队顺序处理，同一条流量先创建、后完成。开始任务非阻塞：队列满了，这条流量整段留在连接上，创建发生在 `RoundTrip` 之前，完成发生在写出之后。已经入队的流量，完成任务等到有空位再入队，不改成就地更新，避免完成跑到创建前面。

记录器只有一个。大响应的解压会拖慢后面几条在界面上变成完成的时间，不拖慢已经写给客户端的响应。

直接调用 `startFlow` 的测试在结束时调用 `Close`，避免记录器泄漏。

## 6. 失败与关闭

出错时的文案保持现在的字符串。

- 上游失败（拨号、TLS、协议错误、拒绝转回代理自己）：写出 `502` 后提交完成任务。请求体只保留已经读到的部分。没有响应正文，不做解压。
- 响应写到一半客户端断开：先把上游剩余正文读进截取缓冲，记上原来的写错误，再提交完成任务。截断标志和原始大小按实际读到的字节计算。有 `Content-Encoding` 时仍尝试解压已截到的那段；解压不了就只留原始字节，不往 `error` 里追加解压失败。
- 客户端 TLS 握手失败：直接 EOF 不记。其余情况记一条 `CONNECT` 失败流量，开始和完成接连入队。错误文案仍是 `TLS handshake with client failed: ` 加上原错误。
- WebSocket：`101` 写失败，或上游连接不能双向转发时，完成任务带上现在的错误文本。

今天会调用 `failUpstream`、`finishResponse` 或 `recordTLSFailure` 的路径，都要提交完成任务。开始任务已经入队的，完成任务等到有空位，不改成就地更新。这条流量的开始任务没能入队的，就地完成。不留下只有创建、没有完成的流量。

`Close` 的顺序：

1. 标记关闭，关掉监听、已接受的客户端连接，以及主传输和 SNI 缓存上的空闲连接。
2. 等待这些连接上的处理退出。退出前它们提交完成任务：开始任务已入队的等到有空位，没入队的就地记录。记录器在此期间一直运行。
3. 记录器把队列里剩下的任务做完再退出。`Close` 等到记录器退出。

`OnUpdated` 返回之前，`Close` 会一直等。`Close` 不取消正在执行的 sink 调用。

## 7. 测试

行为用测试锁死。10 毫秒用本机基准查看，不写入 `go test` 的失败条件。

连接复用：

- 对同一 HTTPS 主机连续 5 个小请求，上游只接受 1 次 TCP。HTTP/1.1 和 HTTP/2 各测一次。
- 上游只协商 HTTP/1.1。六条到代理的连接同时各发 1 个请求，上游接受 6 次；全部结束后再发 1 个请求，接受次数仍是 6。
- CONNECT 到 IP、SNI 为域名时，连续两次请求，上游只接受 1 次 TCP，响应内容正确。
- 测试在第一次拨号前打开 `DisableKeepAlives`，迫使每个请求新建 TCP。上游只协商 HTTP/1.1。服务端第一次 `DidResume == false`，第二次 `DidResume == true`。默认配置不关闭 keep-alive。

记录不挡转发：

- 第一次 `OnUpdated` 被堵住时，同一客户端连接上的第二次请求仍能读完响应。放开之后，两条流量的头和正文都在。
- 队列容量设为 1，并拦住记录器，使它先不取任务。第一条请求的开始任务占住队列，上游不返回。第二条请求看到队列已满，走就地记录：正文仍按 `max_body` 截取，`OnCreated` 在它自己的 `RoundTrip` 之前，`OnUpdated` 在写出之后。放开记录器后，第一条的完成事件排在它自己的创建之后。

原有抓包测试继续覆盖截断、gzip 原文转发加解压副本、HTTP/2、WebSocket、TLS 握手失败和自代理拒绝。这些流量都已 `OnUpdated` 之后 `Close` 才返回。

`BenchmarkWarmHTTPS`：本机 TLS，1 KB 响应，同一条保持连接的客户端。代理和直连各丢弃一次预热。然后各至少测 20 次完整往返（写出请求到读完响应）。通过线是两个中位数之差不超过 10 毫秒：经代理的中位耗时减去直连的中位耗时。基准只打印结果。实现完成时在开发机上跑一次。

叶子证书第一次签发、大文件吞吐和界面帧率不在本次测试范围内。
