# 代理优先、四面板与 Hosts 改写设计规格

**日期：** 2026-11-22  
**状态：** 已批准（对话确认）  
**范围：** 产品定位从「抓包工具」改为「HTTP/HTTPS 代理，抓包是可选能力」；新增首页与 Hosts 面板，抓包独立成面板；抓包关闭时 HTTPS 全程隧道；Hosts 支持多套配置并即时切换；首页展示实时客户端来源。流量列表、详情、过滤、证书签发和转发协议保持现有实现。

## 1. 目标

1. 用户不装 CA、不抓包时，httpproxy 就是一个可用的 HTTP/HTTPS 代理。
2. 左侧活动栏提供四个面板入口：首页、抓包、Hosts、设置。首页是默认面板。
3. 抓包开关关掉后，HTTPS 一律按隧道转发，不签发叶子证书、不需要 CA；打开后才解密并按规则记录。
4. Hosts 像系统 hosts：把域名指向指定 IP，只影响代理向上游拨号。可以保存多套命名配置，任选一套启用，也可以全部不启用。启用哪套记录在 `config.yaml`。
5. 首页展示代理地址、运行时长、抓包状态、当前 Hosts、CA 下载，以及实时客户端列表：哪些 IP 在连、连接数、请求数、HTTPS 连接数、最近活动和最近访问的域名。客户端统计不依赖抓包，抓包关闭时也工作。

成功标准：

- 关掉抓包后，浏览器或 curl 通过代理访问 HTTPS 不需要信任 httpproxy 的 CA，列表不再新增记录。
- 打开抓包后，行为与现在一致：命中规则的流量解密并记录，未命中的按「未抓 HTTPS」处理。
- 切到某套 Hosts 配置后，下一次上游连接就拨到映射 IP；HTTPS 的 SNI 和证书校验仍是原域名。
- 首页每 2 秒刷新一次客户端列表；重启进程后统计清零。
- 旧 `config.yaml` 不加字段也能启动，`hosts_profile` 默认为空。
- 新装的 `config.yaml` 默认 `capture: false`，第一次启动不装 CA 也能通过代理访问 HTTPS。

## 2. 非目标

- 不做进程级归属（看不到「哪个应用」），只按客户端 IP 聚合。
- 不做按客户端、按来源的差异化策略；一套 Hosts 对所有客户端生效。
- 不做 Hosts 通配符、正则、端口映射、域名别名。只做精确域名到 IP。
- 不自动导入 `/etc/hosts`，不支持直接编辑系统 hosts；只管理 `.httpproxy/hosts/` 下的文件。
- 不持久化客户端统计和历史；不做流量图表、字节统计、告警。
- 不监听文件系统变化；外部改文件后由面板刷新或重新启用来生效。
- 不改请求/响应内容，不做改包、重放、上游代理链。
- 不为 Hosts 增加命令行覆盖；不新增 `-hosts` 之类 flag。
- 不用 WebSocket 推送客户端列表；首页用轮询。
- 不做浏览器自动化测试；前端只补纯函数测试。

## 4. 抓包开关语义

抓包开关只有一个状态，继续存在 `config.yaml` 的 `capture`。

| 状态 | 明文 HTTP | HTTPS |
| --- | --- | --- |
| `capture: false` | 正常转发，不记录 | 一律 `CONNECT` 后 TCP 隧道，不解密、不签发证书、不需要 CA |
| `capture: true` | 按现有策略，命中才记录 | 按现有策略：命中记录；未命中按 `capture_https` 解密或隧道 |

- `capture_https` 只在 `capture: true` 且未命中规则时有意义。抓包关闭时它被忽略，界面上注明。
- 结论分层：每个新 `CONNECT` 在开始时确定「解密还是隧道」，明文请求按请求确定；是否记录则在每条请求、每个 HTTP/2 stream 上按当前策略重新判断。对已经解密的连接，重判只决定记不记录：`Record` 才记录，`Tunnel`/`DecryptOnly` 都按不记录转发。因此暂停抓包会立即停止新增记录，已解密的连接继续转发但不再记录，无法退回隧道；恢复抓包后这些连接按当前规则继续记录。已经开始的请求保持本次结论。
- 抓包关闭时，已有记录保留；列表不新增。清空仍然可用。
- 抓包开关出现在首页和抓包面板，两处都是 `PUT /api/capture`，写 `config.yaml`。
- 抓包关闭时首页的 CA 区块显示「抓包关闭时不需要安装 CA」，下载按钮仍可用（为下次开启预留）。
- 新装默认 `capture: false`：首次启动就是纯代理，不装 CA 也能直接跑 HTTPS。已有 `config.yaml` 里的值不变；`Defaults()`、新建文件和 README 的默认字段列表同步改为 `false`。

`internal/capture` 的 `Decide` 改为：

```text
if !capture:
    if https: Tunnel
    else:     DecryptOnly   // 转发，不记录
if https && tunnel && !matches: Tunnel
if matches: Record
else: DecryptOnly
```

## 5. Hosts 配置

### 5.1 文件布局

```text
<workdir>/.httpproxy/
  config.yaml              # hosts_profile: "测试环境"
  hosts/                   # 目录，启动时创建，mode 0700
    测试环境.hosts          # 一个配置一个文件，UTF-8 原始文本
    预发.hosts
```

- 文件名去掉 `.hosts` 就是配置名。只读取 `.hosts` 后缀的普通文件；其他文件、子目录、隐藏文件忽略。
- 配置名与文件名一一对应，允许中文、字母、数字、空格、`-`、`_`、`.`，长度 1–64；不能以 `.` 开头，不能是 `.` 或 `..`，不能含路径分隔符或控制字符。保存前去掉首尾空白。
- 排序按名称做不区分大小写的字典序；当前启用的排最前。
- 同一目录下同名只可能有一个文件；大小写不同的名称在大小写不敏感文件系统上视为冲突，创建/重命名时拒绝。
- 目录不存在时在启动阶段创建；创建失败按启动错误处理。

### 5.2 当前启用哪套

`config.yaml` 新增字段：

```yaml
hosts_profile: "测试环境"   # 空字符串表示不启用
```

- 默认 `""`。YAML 缺键或为 `null` 时按 `""` 读取，不改写文件；保存时总是写出。
- `PUT /api/config` 的 JSON 必须带 `hosts_profile`（字符串）。缺失或类型不对按现有「配置缺少字段」/新错误处理。
- 没有命令行覆盖；`file` 与 `runtime` 始终相同。
- 启动时若 `hosts_profile` 非空：文件必须存在且能通过 5.3 的解析，否则进程以状态 1 退出，向标准错误输出 `hosts: ` 加英文原因（含文件名和行号）。这是为了避免静默把流量发到真实域名。
- 运行中删除当前启用文件不被允许；外部删掉后，下次启动会报错，面板刷新会显示「文件不存在」。

### 5.3 文件格式

与系统 hosts 同构：

```text
# 指向本地联调环境
10.0.0.5   api.example.com
10.0.0.6   cdn.example.com static.example.com
::1        v6.example.com
```

- 每行 `<IP> <域名> [域名...]`，用空白分隔。IP 在前。
- 空行忽略；`#` 到行尾是注释，可以整行也可以跟在条目后面。
- CRLF 兼容，按 UTF-8 读取。文件最大 1 MiB，最多 1000 条域名映射（按文件里出现的映射行计，含重复行）；生效条目是去重后的唯一域名数。
- IP 必须是合法的 IPv4 或 IPv6 字面量。域名必须符合 DNS 语法：标签 1–63 字符，总长不超过 253，字母/数字/`-`，不以下划线开头，不要首尾点；大小写不敏感，保存原样，匹配时小写化并去掉一个末尾点。不接受 `*.`、端口、协议、路径、`@`。域名本身是 IP 字面量的行拒绝。
- 同一文件里同一个域名出现多次不报错，按操作系统读取 hosts 的顺序取第一条，后面的重复行忽略（不做「后者覆盖」，也不作为备用 IP）。
- 被忽略的重复行在面板里作为非阻塞提示显示，例如「第 5 行与第 3 行重复，已按第 3 行生效」，不影响保存、启用和代理运行。
- 语法错误定位到行：`第 3 行：IP 不合法`、`第 5 行：域名不合法`。

解析结果是一个精确匹配表：

```go
package hosts

type Table struct{ /* map[string]net.IP */ }

type Warning struct {
    Domain      string
    IgnoredLine int
    FirstLine   int
}

func Parse(data []byte) (Table, []Warning, error) // 行级错误；Warning 是非阻塞提示
func (t Table) Lookup(host string) (net.IP, bool)
func (t Table) Len() int                          // 去重后实际生效的域名数
```

### 5.4 匹配与拨号

- 只影响代理到上游的拨号，不改系统解析。优先于系统 `/etc/hosts` 和 DNS。
- 只处理请求目标是域名的情况；目标是 IP 字面量时保持原样。
- 端口沿用客户端请求的端口；Hosts 条目不写端口。
- HTTP 明文：`http://api.example.com:8080` 拨到 `10.0.0.5:8080`。
- HTTPS 解密：`CONNECT api.example.com:443` 后，上游 TCP 拨到 `10.0.0.5:443`，但 TLS 的 `ServerName`、证书校验和 `Host` 头仍是 `api.example.com`。
- HTTPS 隧道（抓包关闭或未命中且 `capture_https: tunnel`）：先按映射拨 TCP，再把 TLS 字节原样对拷；客户端自己校验 `api.example.com` 的证书。
- 抓包规则匹配始终用原域名/authority，Hosts 改写不改变抓不抓。
- 映射后的 `IP:端口` 如果等于代理自己的监听地址，拒绝连接，回 502，文案沿用 `refusing to proxy to the proxy's own listen address\n`，避免自环。
- 改 Hosts（启用、停用、保存当前启用文件）后：
  - 立即替换解析表。
  - 关闭主上游连接池和所有 SNI 连接池的空闲连接，下一次请求重新拨号。
  - 已经进入处理的请求和已经建立的隧道不打断，继续使用旧 IP。
  - 抓包列表不因切换 Hosts 清空。
- 抓包详情里显示本次请求实际拨到的 `IP:端口` 和命中的配置名；没有命中时不显示。Flow 新增 `upstream_addr`（如 `10.0.0.5:443`）和 `hosts_profile` 两个字段，只在改写生效时填。隧道不产生 Flow，所以只在首页域名列表里体现。

### 5.5 配置文件生命周期

- 读取：面板打开、保存、启用时读目录。`GET /api/hosts` 解析所有文件用于显示条数和错误，不返回未启用文件的全文。
- 新建：创建空文件；创建后选中编辑，不自动启用。
- 保存：先解析校验，通过后原子写文件（临时文件 + rename）。当前启用的文件保存成功后立即重新编译并应用；未启用的只落盘。
- 重命名：目标名不能已存在。先写新文件，再改 `config.yaml`（如果它是当前启用），最后删旧文件；任一步失败则回滚已做的步骤。重命名未启用配置只做文件 rename。
- 删除：当前启用的配置不能删，返回 409，文案「当前启用的 Hosts 配置不能删除」。其他直接删文件。
- 外部修改：Hosts 面板每次打开/刷新、`GET /api/overview` 每次轮询（首页 2 秒一次）都检查当前启用文件的 `mtime`/大小；变了才重读。内容与上次应用的不一致时尝试重新编译并应用；失败则保留上一次有效规则，面板和首页显示「当前启用的 Hosts 配置有误」，旧规则继续生效。应用成功后按 5.4 关闭空闲上游连接。不监听文件系统。
- 应用失败（语法错误、文件消失）不写 `config.yaml`；当前启用状态保持不变。

## 6. 客户端来源统计

新增进程内 `internal/clients` 跟踪器，与 Flow 记录解耦。

```go
type Client struct {
    IP          string   `json:"ip"`
    ActiveConns int      `json:"active_conns"`
    Requests    int      `json:"requests"`
    Tunnels     int      `json:"tunnels"`
    LastSeen    time.Time `json:"last_seen"`
    Hosts       []string `json:"hosts"`   // 最近访问，最多 8 个
}
```

采集点：

| 事件 | 动作 |
| --- | --- |
| 代理接受一条 TCP 连接 | 按 `RemoteAddr` 的 IP 建条目，`ActiveConns++` |
| 连接关闭 | `ActiveConns--`，更新最近活动 |
| 明文 HTTP 请求 | `Requests++`，记录 `Host`（去端口） |
| 解密后的 HTTPS 请求（HTTP/1.1 或 HTTP/2 每个 stream） | 同明文 |
| 任一 `CONNECT` | `Tunnels++`，记录 CONNECT 的域名 |

- 抓包关闭时仍统计：明文请求、HTTPS 隧道都能看到。
- 统计只按 IP 聚合，不区分源端口，不显示进程名。默认只监听 `127.0.0.1` 时只有一行 `127.0.0.1`；绑到局域网后才会出现多行。
- 内存保存，进程重启清零。`DELETE /api/flows` 只清 Flow，不动客户端统计。
- 清理：没有活跃连接且最近活动超过 5 分钟的条目在读取快照时移除；最多保留 200 个 IP，超出按最近活动淘汰。
- 最近访问域名去重，新的排前面，最多 8 个；界面显示前 3 个，其余放进 `title`。

## 7. API

沿用现有 JSON 错误形状，新增行号时加可选字段。

### 7.1 新增与变更

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/overview` | 首页数据：代理地址、UI 地址、启动时间、运行秒数、抓包状态、Flow 条数、当前 Hosts 名、规则数、Hosts 错误、客户端快照；会顺带检查当前启用文件是否变了 |
| GET | `/api/hosts` | `{active, active_error, profiles:[{name, rules, warnings, error}]}`；`warnings` 是 `[{domain, ignored_line, first_line}]`；会重读目录并应用当前启用文件 |
| GET | `/api/hosts/{name}` | `{name, content}`；不存在 404 |
| PUT | `/api/hosts/{name}` | 请求 `{content}`；校验后写文件；若是当前启用则立即应用。成功 `{name, rules, warnings}` |
| POST | `/api/hosts` | 请求 `{name}`；创建空文件；已存在 409 |
| PUT | `/api/hosts` | 请求 `{active}`；切换当前启用配置，`""` 表示不启用。校验并应用后写 `config.yaml`。这样 `active` 也可以作为配置名 |
| POST | `/api/hosts/{name}/rename` | 请求 `{name}`（新名字）；重命名并同步 `config.yaml` |
| DELETE | `/api/hosts/{name}` | 删除非当前启用的配置；当前启用 409 |
| PUT | `/api/capture/rules` | 请求 `{capture_empty, capture_https, capture_hosts}`；合并保存并应用，不动 `capture` 和 `hosts_profile` |
| GET | `/api/config` | `file` / `runtime` 增加 `hosts_profile` |
| PUT | `/api/config` | 必须带 `hosts_profile`；保存后同步应用 Hosts |
| PUT | `/api/capture` | 不变；关闭时新连接按第 4 节隧道 |

`{name}` 使用 URL 编码。名称里的空格、中文都由路径转义处理。

### 7.2 `/api/overview` 形状

```json
{
  "proxy": "127.0.0.1:18080",
  "ui": "127.0.0.1:17070",
  "started_at": "2026-11-22T00:00:00Z",
  "uptime_seconds": 720,
  "capture": true,
  "flow_count": 128,
  "hosts_profile": "测试环境",
  "hosts_rules": 2,
  "hosts_error": "",
  "clients": [
    {
      "ip": "127.0.0.1",
      "active_conns": 2,
      "requests": 128,
      "tunnels": 3,
      "last_seen": "2026-11-22T00:11:00Z",
      "hosts": ["api.example.com", "cdn.example.com"]
    }
  ]
}
```

首页每 2 秒轮询一次，仅在首页可见时轮询。`flow_count` 由 store 提供计数方法。`hosts_error` 来自当前启用文件最近一次检查/应用的结果；重复行提示只放在 Hosts 面板，overview 不返回。

### 7.3 错误

| 场景 | HTTP | 文案 |
| --- | --- | --- |
| 配置名不合法 | 400 | `配置名不合法` |
| 配置已存在 | 409 | `同名配置已存在` |
| 配置不存在 | 404 | `配置不存在` |
| 删除当前启用配置 | 409 | `当前启用的 Hosts 配置不能删除` |
| Hosts 语法错误 | 400 | `第 N 行：<原因>`，JSON 带 `line` |
| 当前启用配置无效 | 400 | `当前启用的 Hosts 配置无效` |
| 保存配置失败 | 500 | `无法写入配置` |
| 映射后指向代理自身 | 502 | `refusing to proxy to the proxy's own listen address\n` |

行级原因：`IP 不合法`、`域名不合法`、`缺少字段`、`文件超过 1 MiB`、`规则超过 1000 条`。重复域名不是错误，不进入这张表。

## 9. 错误处理与启动

- 启动顺序：读配置 → 读当前 Hosts 文件并编译 → 创建代理。Hosts 错误直接退出，输出 `hosts: <file>: <line>: <原因>`。
- `hosts/` 目录创建失败、不可读、不可写：启动失败，输出 `hosts: <原因>`。
- 运行中某次保存/启用失败：文件、`config.yaml`、代理规则都保持原样，界面显示接口文案。
- 首页快速切换失败：选择回退，显示错误。
- 客户端跟踪器失败（内存不足等）不影响代理转发；统计只是辅助。
- 抓包关闭后的隧道失败沿用现有 502 文案。
- 所有新 API 错误使用第 7.3 节中文文案；启动期和配置文件解析错误保持英文。

## 12. 决定记录（实现者按此执行）

以下是我在对话中定下的判断，用户可在审阅时推翻：

1. 抓包关闭 = HTTPS 全程隧道，不需要 CA。
2. Hosts 采用「一个配置一个 `.hosts` 文件」，当前启用写在 `config.yaml` 的 `hosts_profile`。
3. 只做精确域名匹配，不做通配符和端口；同一文件内域名重复时按文件顺序取第一条，后面的忽略，不报错，只给非阻塞提示。
4. 客户端统计按 IP 聚合，只看机器/客户端，不做进程归属。
5. 删除顶栏；首页承接代理信息和 CA，抓包面板承接开关/计数/清空，设置只留应用级配置。
6. 抓包三项规则从设置页搬到抓包面板。
7. 首页客户端列表用 2 秒轮询，不用 WebSocket。
8. 当前启用配置无效时启动失败；运行中外部改坏则保留上一次有效规则并提示。
9. 删除当前启用配置被拒绝；改名允许并同步 `config.yaml`。
10. Flow 详情显示实际上游地址和命中的 Hosts 配置名。
11. 是否记录在每条请求/每个 HTTP/2 stream 上按当前策略重新判断；暂停抓包对已解密连接立即生效，只停止记录，不停止转发。
12. 解析器返回非阻塞 `warnings`，API 的列表和保存响应都带；overview 每次轮询检查当前启用文件，首页能看到外部改坏；启用/停用走 `PUT /api/hosts`，所以配置名可以是 `active`。
13. 新装默认 `capture: false`；已有配置保留原值。
